# Format Selection

Use this matrix before building a document or presentation.

| Condition | Prefer HTML Document | Prefer PPT |
|---|---|---|
| Rapid drafting and sharing by link | Yes | No |
| Long-form analysis or report | Yes | No |
| Codebase architecture review | Yes | No |
| Executive or client-facing formal meeting | Sometimes | Yes |
| Strict corporate template required | No | Yes |
| Lightweight single-file handoff | Yes | No |
| Offline editing in Microsoft Office | No | Yes |
| Interactive demos during delivery | Yes | Sometimes |
| Team editing inside PowerPoint | No | Yes |

## Default Rules

1. If audience and venue are unclear, start with HTML Document for speed.
2. If stakeholders expect editable Office deliverables, choose PPT early.
3. For analysis, reports, and detailed content, default to HTML Document.
4. For heavy interactivity, author in HTML Document and produce PPT summary for distribution.
5. For executive final delivery, provide PPT even if HTML is source.

## Input Checklist

- Audience: who will decide based on this content?
- Objective: inform, persuade, or request approval?
- Venue: browser, webinar, projector, or file exchange?
- Editing model: single author or multi-editor collaboration?
- Brand constraints: strict template or flexible visual language?
- Content type: general, codebase-analysis, or technical-writeup?
