# Commit and push

Use the repository explicitly named by the user. Inspect its status, branch, remote and diff before staging. Stage only task-owned files. Check for credentials and private data in the staged patch. Run appropriate verification, commit with a concise message, and push the explicit branch only when authorized. Never assume a repository, visibility, default branch, or remote owner. Never force-push unless the user expressly requests the specific history rewrite. Report the resulting commit and remote branch.
